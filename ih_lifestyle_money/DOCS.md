# Lifestyle Money

The admin-only Money page in Home Assistant lets you add and edit contracts, lease payments, balance snapshots, settlement quotes and reminders. The page talks to the add-on through Home Assistant ingress and never needs the API token. Existing fields and reminder history are retained when a record is edited. The dashboard sensor refreshes hourly.

The Move planner imports a private `ih-money-planner-v25` JSON file, stores the scenario and starting assumptions in the add-on's SQLite database, and lets you edit and save them. Download a backup before replacing an existing planner. An optimistic revision check refuses stale saves. Planner assumptions are independent of the live loan records: changing one does not update the other. Inputs and calculated outputs stay in the add-on and browser.

The planner replicates the earlier model's monthly repayment, affordability, equity and target-age calculations. Its early repayment charge and residential stamp-duty bands are fixed approximations inherited from the original planner; they are not guaranteed to match a lender, current legislation, location or eligibility. Verify assumptions and figures independently. The imported v25 file contains the embedded defaults, not any separate unsaved browser changes.

Start and end dates can be left blank when they are not known. A contract without an end date has no scheduled end reminder. A loan balance date may specify a month (YYYY-MM) when the exact day is not known.

Lease cards with a recorded balance, monthly payment and payment day show that snapshot and a dashed scheduled-payment estimate. Every point after the snapshot is an assumption, including any past payments; it is not payment history. The graph clamps the last estimate to zero, handles short months, and is omitted when information is missing or the estimate exceeds 600 payments. Payment estimates are also available as text. Settlement quotes are separate dated snapshots.

Loan and mortgage records can include an account number, provider, notes and dated changes to the balance, interest rate, payment or provider. One-off and monthly overpayments can be planned; a later monthly amount of zero stops the plan. The graph compares the plan against the same loan without planned overpayments. The initial balance, rate and monthly payment are the starting point; dated changes must be after the starting balance date. A later balance is a new recorded snapshot, not an estimate.

For mortgages, add a mortgage term end as well as the current rate or deal end to see the agreed period in green and an illustration for the remaining term in grey. The illustration carries the last known rate forward unless another rate is recorded; it is not a forecast of the future rate. Planned overpayments appear as a blue comparison line.

The graph is illustrative: it applies dated changes within their month, calculates nominal annual interest divided by 12, and assumes scheduled payments. A recorded balance replaces the entire calculation for that month. It omits fees, daily accrual and exact payment dates, so figures can differ from the lender. It stops at a known rate end unless a replacement rate starts by the following day, at contract end or after 600 months. Dates on projected points indicate months, not actual payment days.

This add-on stores private contract records in `/data/money.db`. Set a unique API token. Its internal port is not published to the LAN. The health endpoint exposes no financial data; all other endpoints require the token.

The authenticated `POST /import` accepts an object with `contracts` (a list) and `sent` (a mapping of legacy reminder keys to dates). The import is atomic and accepted only when the database is empty. Send both the existing records and reminder history together; keep the originals and verify the imported result before any cutover.

`GET /contracts` returns records with calculated lease projections. Authenticated `PUT /contracts` saves a complete contract by ID; it replaces that record and keeps reminder history. `GET /reminders` lists due reminders excluding imported sent keys. Enable `publish_sensor` to publish a separate `sensor.lifestyle_money_contracts` every hour. It defaults off and never overwrites the legacy sensor. Rows and `md` include the fields needed by the existing dashboard.

Reminder delivery defaults off. To enable it, configure `assistant_url`, `assistant_token`, and `recipient_personas` as a list of `recipient=persona` mappings for every recipient in the private records. Turn on `reminders_enabled` only after the old reminder sender is stopped. Checks run hourly after 08:00 local time. The Assistant must be live: a dry-run response is not considered delivered. Each recipient is recorded before the request; a timeout, error, dry-run or interrupted request leaves an `uncertain` delivery that will not retry automatically. Inspect `GET /deliveries` with the API token. After checking whether the person actually received it, use `POST /deliveries/resolve` with `key`, `recipient` and `resolution` set to `sent` or `retry`. Retrying an actually delivered message will duplicate it. An unmapped recipient prevents that reminder from being sent at all.

Before switching, back up the original files and add-on data. Validate locally with `python3 tools/migrate_legacy.py --contracts <path> --sent <path>`; it prints counts only. Stop the legacy sender before taking the final snapshot, so no new sent entry can be missed. Import once with the same command plus `--apply --url <internal-api-url>` and `MONEY_API_TOKEN` in the environment. The tool validates both files, imports atomically, verifies the returned records and reports counts; if interrupted after import, inspect the database before retrying. Verify the new sensor and dashboard before changing the dashboard's entity references and enabling reminders. Preserve the old files and the means to restore the old configuration. Never operate both reminder senders at once.

Projected balances assume scheduled payments were made; settlement quotes are dated snapshots. Requests and financial values are not logged. Back up the add-on data before modifying or uninstalling it.
